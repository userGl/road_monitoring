## Детекция дефектов дорожного полотна (MVP)

Минимальный прототип сервиса для детекции дефектов дорожного полотна с помощью модели YOLO, доступный через REST API и Jupyter Notebook.

---

### 1. Описание проекта

Проект представляет собой микросервис на FastAPI   
  
Планируемая технологическая схема обработки видеоданных для выявления дефектов дорожного покрытия и классификации по степени риска

```text
Кадр с камеры
   ↓
Изменение размера / нормализация
   ↓
Маска области дороги
   ↓
Обнаружение дефектов (нейросеть)
   ↓
Постобработка обнаружений
   ├─ фильтрация по уверенности и размеру (для каждого класса)
   └─ подавление пересечений (NMS) между рамками
   ↓
Сопровождение дефектов (трекер)
   ├─ сопоставление рамок между кадрами
   ├─ обновление траекторий дефектов
   └─ подтверждение устойчивых траекторий / удаление нестабильных
   ↓
Вычисление признаков и первичная классификация риска
   ├─ выбоины: площадь рамки
   ├─ трещины: диагональ рамки, оценка длины
   └─ учёт минимальных порогов значимости по размерам
        ↓
        ├─ дефект «несущественный» → траектория отбрасывается
        └─ дефект «существенный» → продолжение обработки
   ↓
Геопривязка дефекта
   ├─ центр рамки → смещение на дорожной поверхности (вдоль / поперёк)
   ├─ увязка с навигационным треком по времени
   └─ оценка координат по кадрам траектории и/или лучшему кадру
   ↓
Выбор наилучшего кадра траектории
   ├─ расчёт показателя качества кадра
       (взвешенное гармоническое среднее уверенности, размера, резкости)
   └─ выбор кадра с максимальным значением показателя
        ↓
        ├─ однозначный случай → основной кадр сразу в медиаданные
        └─ пограничный случай → основной кадр на уточняющую обработку
   ↓
Уточняющая обработка (для пограничных случаев)
   ├─ сегментация области повреждения
   └─ уточнённый расчёт площади, длины и других параметров
       → обновлённый риск
   ↓
Проверка конфиденциальности по сохраняемым данным
   ├─ поиск людей, транспорта, лиц, номерных знаков
   └─ размывание / маскирование при необходимости
   ↓
Сохранение пакета данных о дефекте
   ├─ изображение дефекта (лучший кадр)
   ├─ видеофрагмент вокруг лучшего кадра (при необходимости)
   ├─ класс дефекта и итоговый риск
   ├─ координаты дефекта
   └─ рассчитанные признаки и служебные метаданные

1.	Захват и предварительная обработка кадра.
С камеры поступает очередной кадр видеопотока. Изображение приводится к фиксированному размеру и нормализуется по яркости и цвету, что обеспечивает корректную работу последующих этапов обработки.
2.	Ограничение зоны анализа дорожной областью.
На кадр накладывается заранее определённая маска области дороги (планируется многоугольник в нижней части кадра). Обнаружение дефектов в дальнейшем выполняется только в пределах этой зоны, что уменьшает количество ложных срабатываний на тротуарах, обочинах и посторонних объектах.
3.	Обнаружение дефектов дорожного полотна.
Кадр в пределах маски дороги подаётся на вход искусственной нейронной сети, обученной на классах дефектов дорожного покрытия (продольные трещины, поперечные трещины, сетка трещин, выбоины). На выходе формируются рамки (bounding boxes) с классами и значениями уверенности.
4.	Постобработка обнаружений.
Результаты детектора проходят постобработку:
– выполняется фильтрация для каждого класса по минимальному порогу уверенности и минимальному размеру рамки;
– применяется подавление пересечений (NMS) для устранения дублирующих рамок одного и того же дефекта в пределах кадра.
На этом этапе формируется компактный набор валидных обнаружений, пригодный для дальнейшего сопровождения и анализа.
5.	Сопровождение дефектов и подтверждение траекторий.
Отфильтрованные рамки передаются в трекер, реализующий сопровождение по обнаружениям. Для каждого нового обнаружения выполняется сопоставление с активными траекториями дефектов; при совпадении обновляются положение и статистика соответствующей траектории, при отсутствии совпадения создаётся новая кандидатная траектория. Для каждой траектории накапливается статистика по числу успешных наблюдений и устойчивости геометрических параметров (положения и размеров рамки). Траектория переводится в подтверждённое состояние при выполнении критериев устойчивости (наличие дефекта на нескольких последовательных кадрах и ограниченные колебания размеров рамки) и удаляется при длительном отсутствии новых совпадений. На этом этапе определяется только наличие устойчивого дефекта.
6.	Вычисление признаков дефекта и первичная классификация по степени риска.
Для подтверждённой траектории в режиме реального времени вычисляются и усредняются признаки дефекта. Для выбоин определяется площадь рамки. Для трещин анализируется диагональ рамки и на её основе оценивается длина трещины. На основе совокупности этих признаков выполняется первичная классификация по степени риска (например, низкий, средний, высокий) с учётом минимальных порогов значимости дефекта по размерам.
По результатам первичной классификации для траектории возможны три варианта:
– если дефект по своим размерам и другим признакам ниже пороговых значений (например, длина трещины или площадь выбоины меньше установленного минимального значения), он помечается как «несущественный» и исключается из дальнейшего анализа;
– если полученная оценка степени риска является однозначной, траектория помечается как «однозначный случай», для которого уточняющая обработка не требуется;
– если признаки и размеры дефекта находятся в промежуточной области и не позволяют однозначно отнести его к конкретному уровню риска, траектория помечается как «пограничный случай», требующий уточняющей обработки на выбранном лучшем кадре.
7.	Геопривязка дефекта. Для подтверждённой траектории дефекта выполняется оценка положения дефекта на местности. Для каждого кадра траектории по центру рамки дефекта и известным параметрам камеры (калибровка, положение и ориентация камеры относительно дороги) определяется смещение точки дефекта по продольному и поперечному направлениям относительно траектории движения. Эти смещения увязываются с  навигационным данным (GPS/ГЛОНАСС‑треку) по времени кадра, в результате для каждого кадра траектории получается оценка координат дефекта. Итоговое положение дефекта на местности определяется усреднением координат по траектории вместе с остальными характеристиками дефекта.
8.	Выбор наилучшего кадра траектории.
После первичной классификации риска для каждой подтверждённой траектории выполняется выбор кадров, которые будут использоваться для визуального представления и, при необходимости, уточняющих измерений. Рассматриваются только кадры траектории, в которых дефект прошёл фильтрацию по минимальному размеру. Для каждого такого кадра вычисляется показатель качества в виде взвешенного гармонического среднего трёх нормированных величин: уверенности модели, относительного размера дефекта и резкости области дефекта. В качестве основного кадра траектории выбирается кадр с максимальным значением данного показателя.
Далее:
– для однозначных случаев основной кадр используется сразу для формирования медиаданных;
– для пограничных случаев основной кадр используется как входные данные для уточняющей обработки.
9.	Уточняющая обработка для пограничных случаев.
Для траекторий, отнесённых к пограничным по степени риска, уточняющая обработка выполняется на выбранном лучшем кадре. Она включает сегментацию области повреждения и уточнённый расчёт площади и длины.  В результате для каждой подтверждённой траектории формируется окончательная оценка степени риска, полученная либо на основе первичного анализа (для однозначных случаев), либо с учётом уточняющих измерений (для пограничных случаев).
10.	Проверка конфиденциальности и сохранение пакета данных о дефекте.
Перед сохранением медиаданных выполняется проверка конфиденциальности. В пределах выбранного изображения и соответствующего видеофрагмента анализируются объекты, потенциально содержащие персональные данные (люди, транспортные средства, лица, регистрационные номера). При обнаружении таких объектов соответствующие области на изображении и в видеокадрах размываются или маскируются. После применения анонимизации формируется и сохраняется пакет данных о дефекте, включающий изображение дефекта, видеофрагмент, класс дефекта и итоговую оценку степени риска. Исходные непредобработанные кадры видеопотока при этом не сохраняются.
```

### 6. Использование API

#### 6.1. Endpoint детекции

```text
POST /api/v1/test/detect
```

Тест детекции дефектов дорожного полотна.

**Тело запроса (JSON):**

```json
{
  "image": "<base64-строка JPEG/PNG изображения>",
  "confidence_threshold": 0.6
}
```

**Параметры:**

- `image` — строка с изображением в base64 без префикса или в формате `data:image/jpeg;base64,...` (префикс будет автоматически отброшен).
- `confidence_threshold` — необязательный порог уверенности детекции (по умолчанию 0.6).

**Пример запроса с curl (Linux/macOS):**

```bash
IMAGE_B64=$(python - << 'EOF'
import base64
from pathlib import Path

with open("test_images/Czech_002942.jpg", "rb") as f:
    print(base64.b64encode(f.read()).decode("utf-8"))
EOF
)

curl -X POST "http://localhost:8080/api/v1/test/detect" \
  -H "Content-Type: application/json" \
  -d "{\"image\": \"${IMAGE_B64}\", \"confidence_threshold\": 0.4}"
```

**Пример ответа:**

```json
{
  "success": true,
  "timestamp": "2025-01-31T12:00:00.000000",
  "image_shape":,[^3]
  "detections": [
    {
      "class_id": 0,
      "class_name": "pothole",
      "confidence": 0.87,
      "bbox": [100.5, 200.3, 300.7, 400.9]
    }
  ],
  "processing_time_ms": 45.21,
  "message": "Обнаружено дефектов: 1"
}
```

**Структура ответа** задаётся моделью `DetectionResponse`:

- `success` — флаг успешной обработки;
- `timestamp` — время обработки запроса;
- `image_shape` — размеры входного изображения `[height, width, channels]`;
- `detections` — список детекций (`class_id`, `class_name`, `confidence`, `bbox`);
- `processing_time_ms` — время обработки в миллисекундах;
- `message` — текстовое сообщение, в т.ч. с количеством найденных дефектов.

### 7. Демонстрация в Jupyter Notebook

В репозитории предусмотрен демонстрационный ноутбук `jupyter.ipynb`, который:

- загружает тестовое изображение дороги из `test_images/`;
- отображает исходное изображение;
- конвертирует его в base64 и отправляет POST-запрос на `/api/v1/test/detect`;
- выводит в консоль число найденных дефектов, время обработки и подробности по каждому `bbox`;
